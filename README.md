# Склад: Excel, QR-коды и этикетки

Flask-приложение для работы со складским Excel-файлом, сканирования QR-кодов,
составления укладочного листа и печати этикеток на Niimbot B31.
Поддерживается Python 3.11. Используются только библиотеки, которые уже были
в проекте; единый список находится в `requirements.txt`.

## Запуск

Используйте своё окружение Python 3.11 с существующими зависимостями.
Из корня проекта:

```sh
python app.py
```

Открыть `http://localhost:5001` и выбрать Excel-файл через интерфейс.
Как и раньше, выбранный файл и укладочный лист хранятся в памяти процесса;
после перезапуска файл нужно выбрать заново. Загруженные файлы и сохранённые
шаблоны этикеток остаются на диске в `instance/`.

`python app.py` сохраняет прежний запуск с отладкой. Для запуска без отладки:

```sh
python -m flask --app app run --host 0.0.0.0 --port 5001
```

Если GNU Make уже доступен:

```sh
make run
make dev
make test
make check
make routes
make printer-help
```

Интерпретатор, адрес и порт можно изменить:
`make run PYTHON=python3.11 HOST=127.0.0.1 PORT=5001`.
На Windows можно использовать `make test PYTHON="py -3.11"`.
Makefile ничего не устанавливает. Без Make тесты запускаются командой
`python -m unittest discover -s tests -v`.

## Структура

```text
app.py                     точка входа Flask
warehouse/
  __init__.py              create_app(), регистрация компонентов
  config.py                пути и настройки
  repository.py            чтение и запись Excel
  labels.py                QR-коды и штатная разметка этикетки
  label_editor.py          проверка, отрисовка и хранение шаблонов
  routes/                  HTTP-маршруты по функциям приложения
  templates/               HTML
  static/                  CSS, JavaScript, изображения и документы
  assets/                  изображение шапки этикетки
  vendor/niimprintx/        используемый CLI и BLE-драйвер, лицензия
instance/
  label_templates.json     сохранённые пользовательские шаблоны
  uploads/                 загруженные Excel-файлы и вложения
data/                      исходные складские таблицы
tests/                     unittest: Excel, API, этикетки и протокол печати
requirements.txt           единственный список зависимостей
Makefile                   команды запуска и проверки
```

Пути вычисляются относительно проекта, а не текущего каталога терминала.
Для тестов или собственного запуска настройки можно передать в
`create_app({'UPLOAD_FOLDER': ..., 'LABEL_TEMPLATES_FILE': ..., 'EXCEL_FILE': ...})`.
По умолчанию `EXCEL_FILE=None`: таблица выбирается через интерфейс.

## Сохранённое поведение

Адреса страниц и API не изменены. Excel остаётся хранилищем: порядок и
дополнительные столбцы сохраняются при редактировании и удалении всех строк.
Рекомендуемый формат — `.xlsx`; чтение старого `.xls`, как и раньше, зависит
от наличия подходящего движка pandas в окружении.

Сохранена калибровка B31: 203 DPI, этикетка 48 × 30 мм, изображение 384 × 240
точек, плотность 3, одна копия. Редактор использует ту же шапку и рамку.
Одновременные задания печати блокируются внутри одного процесса.
Приложение рассчитано на один процесс и общий выбранный Excel-файл.

Код принтера включён в проект; отдельная установка NiimPrintX, Poetry и
настройка `PYTHONPATH` не нужны. Его лицензия сохранена в
`warehouse/vendor/niimprintx/LICENSE`. Проверки используют имитацию принтера,
поэтому для тестов Bluetooth-устройство не требуется.

## Что изменено при реорганизации

Удалены старый `app-old.py`, неиспользуемый `niimprintx_first`, Tkinter-интерфейс
NiimPrintX и его сборочные файлы, дубли requirements/Poetry и пустой npm lock.
Основной Git-репозиторий сохранён; вложенных `.git` в исходной рабочей копии
не было. Закоммиченное чужое окружение Python 3.12 и существующие wheel-файлы
перенесены в игнорируемую `.local/`: они не входят в исходники, но локальные
копии библиотек не потеряны. Никакие зависимости при реорганизации не устанавливались.

Рабочие таблицы, вложения, статические изображения и пользовательские шаблоны
сохранены. При резервном копировании сохраняйте `data/` и `instance/` вместе
со статическими вложениями. Новые загрузки и журналы исключены из Git.
